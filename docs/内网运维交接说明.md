# 内网运维交接说明（待目标环境验证）

本文与 `deploy/` 是交付准备材料。当前机器没有 Docker，未构建镜像、未发布服务、未创建公网入口。

## 环境与配置

1. 由 IT 固定 Python、Node、PostgreSQL 及 Nginx 的批准版本/镜像摘要，在受控构建机分别使用 `deploy/Dockerfile.api`、`deploy/Dockerfile.web` 构建镜像并归档依赖锁及许可证材料。
2. 配置 `deploy/compose.yaml` 所需的 `POSTGRES_IMAGE`、`API_IMAGE`、`WEB_IMAGE`、数据库凭据、迁移连接、持久目录和 TLS 目录。样例要求这些值显式注入，避免误以默认口令运行。
3. 根据 `deploy/.env.example` 生成受控的 `deploy/.env.runtime`。应用连接使用 finance_app；迁移任务单独注入 finance_owner 的 `MIGRATION_DATABASE_URL`。不要向 API 和 worker 注入数据库超级管理员凭据。
4. `APP_ORIGIN` 必须与浏览器实际 HTTPS 源完全一致，包括非默认端口；`TRUSTED_HOSTS` 是不带协议和端口的主机列表。只开放目录模式。禁用演示模式，不能复制本机演示凭据到试点。
5. PostgreSQL 数据目录按 PostgreSQL 18 官方镜像布局挂载，导出目录 `/data/exports` 由 UID/GID 10001 可写，Nginx 只挂载证书和前端产物，不能读取导出卷。
6. compose 默认将 HTTPS 绑定 `127.0.0.1:8443`。实际内网入口应由 IT 配置反向代理/VPN/内部地址与访问控制；未经网络评审不改为公网监听。

不要将 `docker compose config` 输出或完整环境变量贴入工单/聊天，其中可能包含连接口令。开发数据库生成器及冷备脚本不用于生产部署。

## 初始化与发布顺序

在目标环境完成卷权限和证书准备后，先启动数据库，再执行一次 migration profile 的迁移任务，再启动 API、worker、web。迁移采用冻结 SQL 与后续编号，不在每次 API 启动时自动建表。

空环境首次账号由 `python -m app.bootstrap_admin` 交互创建。工具拒绝已有账号的环境，临时密码用隐藏输入，不写命令行参数。首次登录改密后才能创建项目；由身份管理员经 `/users` 创建实名账号，再由 CFO 经项目授权接口分配范围。身份和业务分工必须由公司指定，不能让演示账号承担试点责任。

验证 `/api/v1/health/live` 和 `/api/v1/health/ready`，再验证浏览器登录、目录字段准入、独立复核、版本失效、整改、快照导出及撤权。生产关闭 OpenAPI 与交互式文档路由；接口契约以交付包中的 docs/openapi.json 为准。

## 备份与恢复

正式环境建议每 12 小时执行批准的 PostgreSQL 一致性备份，校验后复制到独立故障域，监控最近可恢复备份年龄。pg_dump/pg_restore 客户端主版本与数据库匹配；集群角色、配置、证书恢复材料、迁移版本、镜像摘要和导出卷另行归档。使用服务文件/秘密注入，不在命令行或日志写密码。

本次开发依赖仅携带数据库服务端，没有 pg_dump，已完成的是干净关闭集群后的本机物理备份验证。不能将该短停脚本直接配置为生产定时任务，也不能以同盘复制宣称已满足 RPO≤24小时、RTO≤8小时。

恢复到隔离环境后，应校验模式、表数量、版本引用、快照 manifest 和撤权状态；撤销恢复的全部旧会话；重新核验准入、批准记录及导出产物。缺失导出文件时应用会拒绝下载，应在重新审批/验证后重建，不直接绕开鉴权提供文件。完成抽样业务验证并记录实际恢复点、时长后再进行正式切换。

## 监控与回滚

当前已提供健康接口、请求 trace_id、状态码与耗时日志、数据库审计及持久任务状态。内部告警渠道、备份年龄、磁盘容量、审计故障、任务积压和重试告警尚未接入。业务异常任务记录 failed；未知系统异常事务回滚并重试，需要进一步加入告警和有界重试策略。

发布前记录镜像摘要、模式版本与恢复点。当前迁移禁止直接 destructive downgrade；回滚应用版本前验证数据库兼容性。涉及数据库恢复的回滚必须评估发布后新增记录，不能直接覆盖生产库。导出到期文件清理与保留策略待 IT 冻结；当前到期会拒绝下载，不自动删除历史。

## 正式试点前签收

由财务 Owner 验收适用性与模板标准、至少十类代表资料和三类缺口闭环，由 IT 验收目标环境的权限、审计、隔离、容量、备份恢复及故障处理。完成独立账号和目录准入后，才使用获准真实目录；原件、OCR、AI 功能仍保持关闭。
